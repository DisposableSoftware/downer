# Navigation

Opening files and windows.

## Requirements

| ID | Requirement | Status | Verified by |
|----|-------------|--------|-------------|
| `NAV-1` | `downer [FILE\|URI…]` opens each argument in a window of its own. A path is relative to the current folder. A URI is anything GIO can read (`file:` and, with GVfs, others). When Downer is already running, the files open as new windows of the running instance, and the launching process exits. | done | `scripts/manual/open.sh` (headless: two files give two windows; a second launch with a relative path adds a window to the same process) |
| `NAV-2` | A file window (one opened on a file, not a folder) is titled `<file name> — Downer`; folder windows are titled as in `NAV-6`. | planned | `scripts/manual/open.sh` |
| `NAV-3` | Without arguments, Downer opens one window titled "Downer" that shows a centred hint: "No file open", and below it, dimmed, "Open a Markdown file with downer FILE". | done | `scripts/manual/open.sh` (screenshot) |
| `NAV-4` | A file that can't be read (missing, no permission) shows a centred message in its window with the file name and GIO's error text. Downer keeps running. Bytes that are not valid UTF-8 are shown as U+FFFD, and the rest of the file is rendered. A folder opens a folder window instead (`NAV-6`). | planned | `render::tests::invalid_utf8`, `scripts/manual/open.sh` (a missing file shows GIO's message; Downer keeps running) |
| `NAV-5` | When the open file changes on disk, including when an editor saves it by replacing it, the window renders it again within one second, and keeps the vertical scroll position (clamped to the new length). When the file is deleted, the window keeps showing the last version, and renders the file again if it is created again at the same path. | done | `scripts/manual/reload.sh` on Hyprland (an append below the view leaves it unchanged; an atomic rename re-renders at the same scroll position; a shorter file clamps; delete keeps the last version; recreating renders it) |
| `NAV-6` | A path or URI that is a folder opens a folder window: a sidebar on the left lists the folder's Markdown files as a tree (`NAV-7`), and the main view to its right shows the selected file as a file window does (`VIEW`, `NAV-5`; the `VIEW-2` column is centred in the main view). Folder windows always have the sidebar and file windows never do; it can't be hidden. The title is `<file name> — <folder name> — Downer` while a file is shown, and `<folder name> — Downer` otherwise. A folder that can't be listed shows the `NAV-4` message instead. | planned | `scripts/manual/folder.sh` (headless: titles; screenshots of a folder window and a file window) |
| `NAV-7` | The tree lists the files whose GIO content type is Markdown (`text/markdown` or a subtype, so `.md` and `.markdown`), in the folder and in its subfolders at any depth. Hidden files and folders (GIO's `standard::is-hidden`, such as `.git`) are left out, and so are folders with no Markdown file anywhere below them. Symlinks to files are listed; symlinks to folders are not followed. In each folder, subfolders come first, then files, each sorted by name ignoring case, with runs of digits compared as numbers (`2` before `10`). Rows show the file or folder name. The folder is read without blocking the window. | planned | `tree::tests` (filtering, pruning, symlinks, sort order), `scripts/manual/folder.sh` (screenshot of a fixture tree) |
| `NAV-8` | Folders in the tree start collapsed, except the ones that lead to the shown file. Clicking a folder row, or pressing Enter on it, expands or collapses it. Clicking a file row, or pressing Enter on it, shows that file in the main view and marks its row as the current one. Up and Down move between rows. | planned | `scripts/manual/folder.sh` (headless, keyboard: Down and Enter open a file in a subfolder and the title follows; screenshots of the current row) |
| `NAV-9` | When a folder window opens, it shows the first of `README.md`, `README.markdown` and `index.md` (names compared ignoring case) found directly in the folder, with its row current. If there is none, the main view shows a centred hint, "Select a file", or "No Markdown files" when the tree is empty. | planned | `tree::tests` (the choice), `scripts/manual/folder.sh` (a folder with a README, one without, one with no Markdown) |
| `NAV-10` | The tree follows the folder: within one second of a Markdown file or a folder being created, deleted or renamed anywhere in it, the rows change to match `NAV-7`. Expanded folders stay expanded, and the current row stays current. When the shown file is deleted, its row goes, and the main view keeps the last rendering (`NAV-5`). | planned | `scripts/manual/folder.sh` (headless: a new file in a subfolder appears, a new folder with a file appears, a renamed file moves, a deleted one goes; the current row and expanded folders are kept) |
| `NAV-11` | In a folder window, a link whose target, resolved as in `VIEW-6`, is a Markdown file listed in the tree opens that file in the main view and selects its row (expanding the folders above it), as if it had been clicked in the sidebar. A fragment on the link (`other.md#name`) then scrolls to that heading, as `VIEW-6` does. Other links follow `VIEW-6`. | planned | `tree::tests` (which links stay in the window), `scripts/manual/folder-links.sh` on Hyprland (clicking `sub/other.md#part` changes the title and scrolls; an `https` link is not tested, see `VIEW-6`) |

## Implementation notes

- `NAV-1`: `gio::ApplicationFlags::HANDLES_OPEN`; `connect_open` makes one window per `gio::File`, and `connect_activate` (no arguments) makes the `NAV-3` window.
- `NAV-5`: a `gio::FileMonitor` on the file, with `WATCH_MOVES`, so a rename onto the path counts as a change. Reload after a short delay, so a burst of events from one save gives one reload.
- `NAV-10`: a `gio::FileMonitor` per listed folder (`monitor_directory`, `WATCH_MOVES`). A large tree, such as a home folder, means a recursive read and many inotify watches; there is no depth limit.
- `NAV-11`: a link opens in the window only if its resolved URI is one of the tree's files, so links to files outside the folder, or to files the tree leaves out, keep `VIEW-6`.
