## Implementation notes

- Parsing: `pulldown-cmark` with `ENABLE_TABLES`, `ENABLE_STRIKETHROUGH` and `ENABLE_TASKLISTS`. Turning events into a plain block tree, with no GTK types, keeps `render::tests` free of a display.
- Widgets: a vertical `GtkBox` in a `GtkScrolledWindow`. Paragraphs, headings and list items are selectable `GtkLabel`s with Pango markup, which must escape all source text. Tables are a custom widget with wrapping cell labels (`VIEW-10`), and code blocks are labels in a horizontally scrolled window.
- `VIEW-2`: gtk4-rs 0.11 has no `GtkCustomLayout` binding, so `column.rs` is a one-child `gtk::Widget` subclass that measures and centres its child. The width was 800px at first, which held about 100 characters a line in a typical UI font; 60 to 80 characters is the readable range.
- `VIEW-10`: two attempts with `GtkGrid` (wrapping labels in a sideways-scrolling window, then in a plain grid with a minimum label width or equal columns) all made GTK warn "Trying to measure GtkGrid … for height of N, but it needs at least M": the grid's overall minimum height is measured at its minimum width and exceeds its height at the real width. So tables are a one-child-per-cell `gtk::Widget` subclass in `table.rs`, like `column.rs`. One function turns a width into column widths (each column's minimum width plus a share of the spare width in proportion to natural minus minimum, so columns share by content size) and into row heights (the tallest cell's height for its column width). `measure` answers every question from that function: the minimum width is the sum of column minimums, and the height for any width, including the minimum height when no width is given, comes from the same function, so the heights never disagree. Check for GTK warnings in `render.sh`.
- `VIEW-11`, `LOOK-13`: a `GtkLabel` row above the scrolled view, copied from Junk Drawer's path bar (`src/window.rs`, `.path-bar` and `label.path` in `data/style.css`) without the up button. Start-ellipsized, `focusable(false)` and `can_target(false)`.
- Selectable labels select all their text when they get keyboard focus (GTK behaviour). Labels on the hint and error pages are plain, so the first one doesn't start selected.
